### Compatibility contracts

**Multipart video upload.** Exactly two form fields: file field `video` (`request.files["video"]`, server.py:58–61; missing → 400) and text field `settings` (JSON string, default `"{}"`, invalid JSON → 400, server.py:62–66). The uploaded filename is discarded entirely — the file is always saved as `modular_pipeline/jobs/<uuid4>/video.mp4` (server.py:73–74), so no secure-filename handling is needed or performed. Size limit: `MAX_CONTENT_LENGTH = 4 GB` (server.py:50). The `settings` JSON is two-level: outer `{name, durationSecs, customPrompt?}` plus inner `settings` object whose camelCase keys map to snake_case (`frameQuality→frame_quality`, `chunkSizeSecs→chunk_size`, `audioExtraction→audio_extraction`, `detailLevel→detail_level`, `presetStyle→preset_style`; defaults `model:"gpt-4.1"`, `fps:1.0`, `chunk_size:60`, server.py:76–91). The frontend builds this exact shape at App/src/lib/uploadApi.ts:38–40. Response 202 `{jobId, projectId}` where the two values are the same UUID (server.py:69,121) — the frontend relies on this to navigate `/editor/{jobId}`.

**/data/{job_id} directory layout.** `DATA_DIR = App/public/data` (storage.py:20), served by `send_from_directory` (server.py:787–789). The pipeline writes, per job: `scenes.json`, `audio_events.json`, `ad_placement_gaps.json`, `transcript.json`, `entities.json` (verified list run_job.py:366–372), plus `poster.jpg` (run_job.py:165–192) and best-effort `poster.avif` (run_job.py:166,194–220). The frontend requests: `{dataPath}/scenes.json` (App/src/lib/api.ts:27), `audio_events.json` (api.ts:35), `ad_placement_gaps.json` (api.ts:42), `entities.json` (api.ts:49), `poster.jpg`/`poster.avif` (via result fields; tutorials.ts:97–98), and in demo builds `tts/scene_<n>_<voice>.mp3` (demoApi.ts:81) and `export.mp4` (demoApi.ts:112) — the committed fixture `App/public/data/sintel-blender-cc/` additionally contains `export.mp4` and `system_info.json`. Two subtleties: (1) `PATCH /entities/<id>` rewrites `entities.json` and `scenes.json` in place with no lock (server.py:444–467); (2) the frontend fetches `dataPath` root-relative with **no** `API_BASE` prefix (api.ts:27 vs api.ts:72), so in dev Vite serves these from `App/public/` while in deploy Flask must be same-origin — a hard single-origin assumption for migration.

**/videos/{job_id}.mp4.** Served by `send_from_directory(storage.VIDEOS_DIR, subpath)` (server.py:792–794) from `App/public/videos/` (storage.py:19). Flask's `send_from_directory` default gives conditional/Range support (required — `<video>` seeking depends on 206 responses; EditorPage.tsx:565) and infers `video/mp4` from the extension. Files arrive there two ways: `run_job.py:377–384` copies `jobs/<id>/video.mp4 → App/public/videos/<id>.mp4` at job completion, and `storage.video_url_for` performs the same copy lazily if `result.json` lacks a `video_file` (storage.py:139–149). Same root-relative/no-API_BASE caveat as `/data`.

**Job status lifecycle.** Statuses the API can emit: `queued` (written at create, server.py:96–107), `processing` (run_job.py:150,155,234,239,276,279,327–330,345), `ready` (run_job.py:395; also fabricated by study provisioning server.py:685–694), `failed` (run_job.py crash handler:417–435), `not_found` (missing status.json, storage.py:63), `error` (corrupt status.json, storage.py:66–72). Stages: `queued`, `initializing`, `extracting_frames`, `transcribing_audio`, `analyzing_frames`, `exporting`, `complete`, `failed`, `unknown`. Progress checkpoints: 2→5→15→16→25→(25+63·done/total)→88→100. Polling route: `GET /api/jobs/<id>` (server.py:127); the frontend's `PollResult` type mirrors it (uploadApi.ts:16–30). Export status files are a separate lifecycle: `queued`/`processing`/`ready`/`failed` with stages `queued`, `writing_{srt|csv|docx}`, `rendering_tts`, `mixing_video`, `extracting_mp3`, `complete`, `video_missing`, `error` (server.py:498–507; export_service.py:73–217).

**Scene overrides.** Route `PATCH /api/jobs/<id>/scenes/<scene_id>` (server.py:391). Payload keys and validation: `ad` str truncated to 8000 (server.py:407), `active` bool, `locked` bool, `voice` must be in `export_service.VALID_VOICES = {onyx, nova, alloy, shimmer, echo, fable}` else **silently dropped** (server.py:412–415; pinned by tests/test_server_api.py:149–152 — the frontend only offers the first four, api.ts:54), `speed` coerced+clamped to 0.5–2.5 (server.py:416–420; tts_render.py:171–181). Storage: whole-file JSON map at `jobs/<id>/scene_overrides.json` (storage.py:41–42). Locking: per-job `threading.Lock` from a guarded registry held across the full read-modify-write (server.py:402; storage.py:97–107) because the editor flushes all scenes in parallel via `Promise.all` before preview/export (EditorPage.tsx:327–329; rationale comment storage.py:90–95); writes are atomic tmp+`os.replace` (storage.py:120–127). Migration-critical: the lock is per-process — any multi-worker/multi-instance deployment silently loses the guarantee, and a dropped override defaults a scene back to `active: True` in the merge (export_service.py:60), i.e. a deactivated scene gets narrated.

**Smart Fill.** `POST /api/jobs/<id>/smart-fill` (server.py:274). Request `{text: non-empty str, target_secs: float > 0}`; `target_secs` capped at 120 s, word budget `max(3, round(target_secs × 2.3))` (server.py:271,293–294). One call to `get_text_provider().rewrite(temperature=0.4, max_tokens=400)` (server.py:314–316) — backend chosen by the provider factory, so "single OpenAI call" is actually provider-pluggable. Symmetric surrounding quotes are stripped from the model output (server.py:318–319). Response `{ad, target_secs, target_words, estimated_secs, tokens_used, model}` (server.py:326–335); provider failure → 500. Demo builds never hit it (App/src/lib/api.ts:177 → demoApi.ts:49–66, deterministic truncation).

**TTS preview.** `POST /api/jobs/<id>/tts-preview` (server.py:341). Request `{text ≤ 4000 chars (400 above), voice default "onyx", speed}`; the frontend also sends `sceneId` (api.ts:75) which the handler ignores — the cache key is content-based, not scene-based. Caching: base render at `jobs/<id>/tts_cache/<sha256("{voice}::{text}")[:24]>.mp3` (server.py:361–364); speed ≠ 1.0 produces a derived `"<key>_s<speed>".mp3` via ffmpeg `atempo` (server.py:376–383; tts_render.py:184–198); both are rendered only on miss. Response: the mp3 via `send_file(mimetype="audio/mpeg", conditional=True)` (server.py:385). Render goes through `tts_render.render_line` → `get_tts_provider()` (tts_render.py:49–54; OpenAI `tts-1-hd` default, Kokoro when local, factory.py:115–131).

**Exports.** Async, thread-based. `POST /api/jobs/<id>/export` validates format (`{mp4, mp3, srt, csv, docx}`, 400 otherwise), coerces bad voice to `onyx` silently (server.py:489–490), 409s until `data/<id>/scenes.json` exists, creates `jobs/<id>/exports/<uuid4.hex[:12]>/status.json` and spawns a daemon `threading.Thread` running `export_service.run_export` (server.py:495–515); returns 202 `{exportId, format, status:"queued"}`. Global semaphore `MAX_CONCURRENT_RENDERS` (env, default 2) queues heavy renders (export_service.py:33–37,78). Text formats (srt/csv/docx, writers in modular_pipeline/exports.py:34–122) are near-instant; mp4/mp3 render per-active-scene TTS (raw→loudnorm→atempo), measure background LUFS per gap, duck when above −35 LUFS, mix with ffmpeg into `export.mp4`, then optionally strip to mp3 (export_service.py:119–206). Status poll `GET .../export/<eid>` returns `status.json` verbatim (server.py:518–528); terminal success adds `download_url` (export_service.py:111–116,208–215). Download `GET .../export/<eid>/download`: format read back from `status.json` (server.py:537–542), file `export.<fmt>`, 404 until it exists, `?inline=1` switches from attachment to inline streaming for the eyes-closed preview (server.py:547–555), download name `instascribe_<job_id[:8]>_<export_id>.<fmt>`, conditional/Range enabled. Frontend flow: requestExport → pollExport loop → exportDownloadUrl (api.ts:137–218; EditorPage.tsx:322–435).

**Project list/rename/star/delete/reconcile.** `GET /api/jobs` with no args iterates the jobs directory (server.py:225–231); with `?ids=` returns a summary for each requested id including missing ones (`status:"not_found"`, via storage.read_status), which the frontend's reconcile skips (uploadApi.ts:152). Summaries merge `status.json` + `settings.json` (project_name, duration_secs, model, chunk_size) + `result.json` (ready fields) + `meta.json`, with meta `name`/`starred` taking precedence (server.py:165–210). `PATCH /api/jobs/<id>` writes only `{name (trimmed, ≤200), starred (bool)}` into `meta.json` and returns the merged meta (server.py:251–265). `DELETE` removes only `jobs/<id>` (server.py:237–245) — `App/public/data/<id>/` and `App/public/videos/<id>.mp4` are orphaned, a cleanup gap any migration must decide about. Reconcile is client-driven: `reconcileProjectsWithServer` (uploadApi.ts:116–179) runs on dashboard mount (DashboardLayout.tsx:71), patching or adding local-store projects; there is no server-side reconcile endpoint.

**Provider status/selection.** `GET /api/providers` → `{backends: [...], current}` (server.py:766–770); readiness computed in `provider_status` (factory.py:140–202) from env presence (`OPENAI_API_KEY`/`OPENAI_BASE_URL`, `ANTHROPIC_API_KEY` + SDK installed, `GEMINI_API_KEY`/`GOOGLE_API_KEY`) and a 0.4 s socket probe of Ollama; only booleans and remediation strings leave the server — key values never do (factory.py:141–143). Keys live in the repo-root `.env` (loaded factory.py:151 and tts_render.py:26) and `modular_pipeline/.env` (api_settings.py:7 — note api_settings.py contains no routes despite its name; it is the OpenAI client helper used only by providers/openai_provider.py:16). `POST /api/providers {backend}` validates against `VALID_BACKENDS = (openai, anthropic, gemini, local, fake)` (server.py:773–781; factory.py:25) and sets the module-global `_OVERRIDE` (factory.py:29–38): **in-memory, unpersisted, per-process** — lost on restart and inconsistent across multiple workers. New pipeline jobs get the choice pinned via the `INSTASCRIBE_BACKEND` env var on the `Popen` (server.py:111–112); in-process calls (smart-fill, TTS, exports) resolve it live per call (factory.py:46–54).

**Fixture demo and study mode — isolation.** Three server routes are study-specific: `POST /api/study/session`, `POST /api/log`, `GET /api/study/config` (server.py:656,725,751). They are always registered — nothing server-side gates them off in a normal deploy; isolation is purely frontend build flags: `VITE_STUDY_MODE=1` (session.ts:12–14, enforced by router guards, guards.tsx:12) and `VITE_DEMO_MODE=1` (session.ts:21–23). Demo builds never touch write/render endpoints at all — api.ts short-circuits to demoApi at api.ts:71,89,109,142,177,193,206,215, with in-memory overrides, local Smart Fill, baked TTS mp3s, and the committed `export.mp4` — running entirely off the checked-in fixture `App/public/data/sintel-blender-cc/` + `App/public/videos/sintel-blender-cc.mp4` (tutorials.ts:95–98), which normal `/data` and `/videos` routes serve. Study mode hits live routes: provisioning `copytree`s the frozen source (`STUDY_SOURCE_JOB`, default `sintel-blender-cc`, server.py:616) into `data/<sessionId>` per participant, fabricates a ready job, seeds all scenes inactive (server.py:700–710, idempotent for returning sessions), and shares the single source video file (server.py:679). Consequently study sessions materialize as real jobs: they appear in `GET /api/jobs` listings and are exportable/deletable by anyone. `/api/log` appends unauthenticated, unbounded JSONL per session (server.py:737–748).

### Anything unroutable

- **No blueprints, no `add_url_rule`** — all 24 rules are direct decorators in modular_pipeline/server.py (grep confirms zero registrations elsewhere). `api_settings.py`, `exports.py`, and `export_service.py` contain no routes.
- **Catch-all is GET-only** (`@app.get("/<path:path>")`, server.py:804): with a `dist` build present, any unknown GET path returns `index.html` (200) instead of 404 except `api/*` (server.py:807–808); non-GET requests to unknown paths get Flask's default 404/405, not the SPA fallback. `/data/...` and `/videos/...` win over the catch-all by Flask rule specificity, not ordering.
- **`GET /api/jobs/<job_id>` skips `JOB_ID_RE` validation** (server.py:127–129) — every sibling mutating handler validates (e.g. server.py:239,253,277). Practical exposure is low (a path segment cannot contain `/`, and it only reads `jobs/<id>/status.json`), but it is an inconsistency a rewrite could accidentally "fix" in either direction.
- **`GET /api/study/config` is frontend-orphaned**: no reference to the route or `questionnaireUrl` anywhere in App/src (grep across `*.ts`/`*.tsx` returns nothing) — reachable, tested (tests/test_server_api.py:268), but dead from the product's perspective.
- **`GET /api/jobs/<id>/evaluation` is frontend-orphaned**: the editor's QualityPanel uses the client-side mirror `App/src/lib/evaluation.ts` (its line 3 declares it "a mirror of modular_pipeline/evaluation.py"; QualityPanel.tsx:5) — two scoring implementations that can drift.
- **`GET /api/jobs?ids=` batch mode has no frontend caller** — only the no-arg list is used (uploadApi.ts:121, SettingsPage.tsx:84); the batch branch survives on tests alone (tests/test_server_api.py:116–118).
- **`voice` values `echo` and `fable` are server-valid but frontend-unreachable** (export_service.py:22 vs the `VoiceId` union of four, api.ts:54).
- **`sceneId` in the tts-preview request body is dead payload** — sent (api.ts:75), never read (server.py:348–350).
- **Handlers assume a single process**: overrides locking (storage.py:97–107), the export semaphore (export_service.py:37), and the provider `_OVERRIDE` global (factory.py:29) are all process-local; `app.run(threaded=True)` (server.py:824) is the only supported concurrency model. Running this under gunicorn with >1 worker would silently break three separate contracts.

### Concurrency & lifecycle notes

**1. Per-job overrides lock (storage.py:97–107, held at server.py:402).** A process-global dict `_overrides_locks` maps job_id → `threading.Lock`, guarded by `_overrides_locks_guard`. It serialises the read-whole-file → mutate-one-scene → write-whole-file cycle in `patch_scene` (server.py:402–423), because the editor flushes every scene in parallel with one PATCH each; the module comment (storage.py:89–95) documents that a lost update resurrects `active=True` and would wrongly narrate a deactivated scene. It is a `threading.Lock` in one Python process: it assumes the deployment is exactly one Flask process with `threaded=True` (server.py:824). Two gunicorn workers, two containers, or an ALB across replicas each get an independent lock dict, and the lost-update bug returns silently. It also does not protect readers in the detached `run_job.py` process (different PID entirely).

**2. Atomic overrides write (storage.py:120–126).** `write_overrides` writes to `scene_overrides.json.tmp` then `os.replace` so a concurrent reader (e.g., `merged_scenes` during an export, export_service.py:47) never parses a torn file. This is the only atomic write in the codebase. It relies on POSIX same-filesystem rename; on NFS/EFS or an S3-backed abstraction the guarantee weakens or vanishes, and it does nothing for cross-container write-write conflicts (last `os.replace` wins wholesale).

**3. Render semaphore (export_service.py:36–37, acquired 78, released 219).** `threading.Semaphore(MAX_CONCURRENT_RENDERS)` (default 2) caps simultaneous TTS+ffmpeg renders so concurrent study participants can't exhaust CPU/memory. Process-local: N containers each admit `MAX_CONCURRENT_RENDERS` renders, so the fleet-wide cap scales with replica count instead of with the shared resource. Needs to become a queue with worker-count concurrency control.

**4. Export execution model (server.py:509–514).** Exports run on a `daemon=True` thread inside the Flask process. A deploy, crash, or container recycle kills the thread mid-render and leaves `exports/{id}/status.json` permanently at "processing" — nothing reconciles it. The status file itself is written non-atomically (`write_text`, export_service.py:76), so the poll endpoint can read a torn file and returns 500 "corrupt status" (server.py:525–528).

**5. Detached job subprocess (server.py:113–119).** `subprocess.Popen` with no stored PID, no `wait()`, no timeout, no cancellation endpoint, and unbounded parallelism (every upload spawns a process immediately). The only failure detection is `run_job.py`'s own top-level except writing `status: failed` (run_job.py:417–435); a SIGKILL/OOM bypasses it and the job is stuck at "processing" forever — there is no startup sweep or heartbeat to reconcile. The Popen object is never reaped (zombie until interpreter GC), and the `stderr.log` file handle opened at server.py:118 is never closed by the parent. This cannot work across containers at all: the job's lifetime is coupled to the API container's lifetime, and status flows only through the shared local file `jobs/{id}/status.json`.

**6. Job status files as IPC (run_job.py:127–139; storage.py:60–72).** Plain `write_text` with no tmp+rename, written up to once per chunk. `read_status` swallows parse failures as "Corrupt status file" (storage.py:66–72), which masks torn reads as a transient error surfaced to the UI. Works only because writer and readers share one local filesystem.

**7. Unlocked read-modify-write sites.** (a) `meta.json`: `patch_job` reads, mutates, writes with no lock and no atomic rename (server.py:259–264) — concurrent rename+star loses one. (b) Entity rename: `patch_entity` reads `entities.json` + `scenes.json`, rewrites both with non-atomic `write_text` (server.py:457–467); concurrent renames race each other, and an export's `merged_scenes`/docx read (export_service.py:45, 95) can observe a half-written file or the inconsistent window between the two writes. (c) TTS preview cache: exists-check then render (server.py:366–371, 378–383) — duplicate concurrent renders write the same path while `send_file` may stream a partial file. (d) Study provisioning: `dst_data.exists()` then `shutil.copytree` (server.py:669–671) — two simultaneous first calls for one session collide with `FileExistsError`; the overrides seed is likewise exists-guarded only (server.py:700–710). (e) Lazy video copy in `video_url_for` (storage.py:142–147) — two requests can `copy2` concurrently into the served path.

**8. Import-time configuration freeze (run_job.py:6–9, 69–91; config.py:12–48).** All per-job paths and model settings are environment variables read into module constants at import time; run_job.py must set env before importing pipeline modules. Consequence: a long-lived worker process cannot run two jobs — the architecture assumes process-per-job — and any queue-based worker must either re-exec or the config layer must be refactored to pass a job context object.

**9. Module-global state.** `_last_word_events`/`_pipeline_cache` (audio_whisperx_pipeline.py:53–60) create a hidden ordering contract: `calculate_ad_gaps` (712–713) only yields word-precision gaps if `load_audio_events` ran earlier in the same process (satisfied by run_job.py:251–263). `_OVERRIDE` backend (factory.py:29–43) set via `POST /api/providers` lives in one process; replicas disagree, restarts reset it, and running jobs see only the env snapshot taken at spawn (server.py:111–112). `_call_count` (api_settings.py:11–18) is a per-process API budget. None of these coordinate across containers.

**10. Semaphore/lock summary for v0.1.** Every mechanism found (`threading.Lock`, `threading.Semaphore`, `os.replace`, exists-checks) is process-local or filesystem-local. Multi-container v0.1 requires: job/export/status state in PostgreSQL (row-level locking replaces #1, #6, #7), a real queue for #3–#5, and S3 conditional/idempotent writes for #7c/e.

### Deletion/cleanup paths

- **`DELETE /api/jobs/<id>` → `shutil.rmtree(jdir)` (server.py:237–245).** Removes only `mp/jobs/{job_id}/` (video, settings, status, meta, overrides, tts_cache, exports). It does NOT remove `App/public/data/{job_id}/` (scenes/entities/audio JSON, posters) nor `App/public/videos/{job_id}.mp4` — deleted jobs leave their full analysis output and video copy publicly served forever. Migration must make deletion transactional across DB + S3 prefixes.
- **Temp WAV cleanup (audio_whisperx_pipeline.py).** `wav_path.unlink(missing_ok=True)` on the no-audio error path (155) and in the `finally` after VAD+transcription (635–636). Leaks on hard kill.
- **Temp transcription script cleanup (audio_whisperx_pipeline.py:431–432).** `script_path.unlink(missing_ok=True)` in `finally`.
- **Kokoro temp WAV cleanup (local_provider.py:138–139).** `wav_path.unlink(missing_ok=True)` in `finally`.
- **Chunk-resume reconciliation (pipeline.py:175–176).** `SKIP_EXISTING and out_file.exists()` reuses prior chunk JSON — the only resume mechanism; run_job.py disables it (`JOB_SKIP_EXISTING=false`, run_job.py:83), so server jobs always recompute from scratch.
- **Missing-output verification (run_job.py:363–375).** Post-export check that the 5 frontend JSON files exist; warns only, does not repair.
- **Idempotent re-provisioning (server.py:666–671, 700).** Study session copytree and override seeding are skipped when the destination exists — reconciliation-by-existence, not by content.
- **No cleanup exists for:** extracted frames (`jobs/{id}/frames/`), work/debug artifacts (memory, chunk outputs, reports), TTS preview cache, export directories and their `tts/` intermediates, study session data copies under `App/public/data/{uuid}/`, study log files, `stderr.log`, the lazily copied public videos, or the whisper model cache. Nothing reconciles jobs/exports stuck in "processing" after a crash — no startup sweep, TTL, or garbage collector anywhere in `modular_pipeline/`.

## 5. Pipeline coupling map
### Invocation contract

- **Command** (server.py:113–119): `subprocess.Popen([storage.PYTHON, str(storage.SERVER_DIR / "run_job.py"), job_id, str(settings_path)], cwd=str(storage.SERVER_DIR), env=job_env, stdout=subprocess.DEVNULL, stderr=open(str(jdir / "stderr.log"), "w"))` — i.e. `<venv python> modular_pipeline/run_job.py <job_id> <jobs/{job_id}/settings.json>`.
- **Interpreter**: `storage.PYTHON = sys.executable` — the same venv python running the server (storage.py:23).
- **Working directory**: `storage.SERVER_DIR` = `modular_pipeline/` (storage.py:17; server.py:115).
- **Env**: `job_env = dict(os.environ)` — full server environment inherited, plus `job_env["INSTASCRIBE_BACKEND"] = active_backend()` pinning the job to the in-app-picker backend at submit time (server.py:111–112). No other env is set by server.py; all `JOB_*` vars are set by run_job.py itself (run_job.py:74–87).
- **Detach mechanism**: fire-and-forget `Popen` — the handle is discarded, never `wait()`ed or stored; no `start_new_session`/`setsid`, no daemonization. The job is an ordinary child of the Flask process.
- **PID tracking**: none. There is no way to cancel or kill a running job; `DELETE /api/jobs/<id>` removes the job dir (server.py:237–245) but not the process.
- **stdout**: discarded (`DEVNULL`, server.py:117). **stderr**: redirected to `jobs/{job_id}/stderr.log` (server.py:118) — the file handle is opened inline and never closed by the server.
- **Settings file contract** (server.py:77–94): keys `job_id`, `video_path` (abs path to `jobs/{id}/video.mp4`), `model`, `frame_quality`, `fps`, `chunk_size`, `audio_extraction`, `custom_prompt`, `language`, `detail_level`, `preset_style`, `project_name`, `duration_secs`. Before launch, server writes `jobs/{id}/status.json` with `{"status":"queued","progress":0,"stage":"queued","chunks_done":0,"chunks_total":0,"error":null}` (server.py:96–107) and returns `202 {jobId, projectId}` (server.py:121).

### run_job.py vs server.py responsibilities

**server.py owns**: HTTP API + static serving (single-origin SPA, server.py:784–813); job creation, settings validation/normalisation, queued-status seeding (server.py:56–121); status/result polling (`GET /api/jobs/<id>`, server.py:127–159; batch list server.py:213–231); job deletion/rename/star (server.py:237–265); post-ANALYZE editing features — smart-fill via text provider (server.py:274–335), TTS preview cache (server.py:341–385), scene overrides (server.py:391–424), entity rename + scene re-render (server.py:430–472); export orchestration in a daemon **thread** not a subprocess (server.py:509–514 → export_service.run_export); study-mode session provisioning/logging (server.py:610–760); provider picker state (server.py:766–781).

**run_job.py owns** (the whole ANALYZE run): prompt assembly from settings (`DETAIL_INSTRUCTIONS`/`STYLE_PREFIXES`/`build_prompt`, run_job.py:39–66); frame extraction (run_job.py:157); poster/LQIP generation (run_job.py:164–232); audio pipeline invocation and empty-file fallback (run_job.py:242–274); chunked LLM analysis loop with memory (run_job.py:282–330); export of frontend JSON (run_job.py:352–361); copying the video into `App/public/videos/` (run_job.py:377–387); writing `status.json` throughout and `result.json` at the end (run_job.py:119–139, 395–410); crash handling (run_job.py:417–435).

**The env-before-import dance** (run_job.py:8–9, 69–114): run_job parses argv and settings (run_job.py:27–29), computes job paths (run_job.py:31–35), then sets `JOB_VIDEO_ID/JOB_VIDEO_PATH/JOB_FRAMES_DIR/JOB_PROJECT_DIR/JOB_OUTPUT_DIR/JOB_MODEL/JOB_IMAGE_DETAIL/JOB_CHUNK_SIZES/JOB_PROMPT/JOB_SKIP_EXISTING` (run_job.py:74–83) and conditionally `JOB_WHISPER_LANGUAGE` (run_job.py:85–87) **before** `sys.path.insert(0, str(PIPELINE_DIR))` and the pipeline imports (run_job.py:91–114), because config.py reads all of them at import time (config.py:12–48). pyproject.toml codifies this: `"modular_pipeline/run_job.py" = ["E402"]` with the comment "run_job.py sets JOB_* env vars before importing config (which reads them at import time)" (pyproject.toml:14–17). Consequence: importing `config` (or anything that imports it — pipeline.py:13–28, memory.py:8, schemas.py:3) freezes all job configuration for the process; per-job configuration is only possible via a fresh subprocess.

For in-`main()` failures it writes `{"status":"failed","progress":0,"stage":"failed","chunks_done":0,"chunks_total":0,"error":<full traceback>}` then `sys.exit(1)` (run_job.py:417–435); the server surfaces `error` in job listings (server.py:201–202). ### Containerization blockers & adapter seam

**Blockers**:
1. **Dependency split**: the deployed image (Dockerfile:17–18) installs only requirements-server.txt, which excludes numpy/torch/faster-whisper/silero-vad/Pillow — `run_job.py` cannot even be imported there (import chain run_job.py:108 → pipeline.py:7 → audio_whisperx_pipeline.py:32 `import numpy`). A worker container needs the full requirements.txt plus ffmpeg (ideally with libsvtav1 for run_job.py:204; AVIF is best-effort so plain ffmpeg is acceptable).
2. **Hardcoded repo-relative layout**: run_job derives everything from its own file location — `PIPELINE_DIR = Path(__file__).parent`, `APP_DIR = PIPELINE_DIR.parent/"App"` (run_job.py:24–25), `JOB_DIR = PIPELINE_DIR/"jobs"/job_id` (run_job.py:31), `OUTPUT_DIR = APP_DIR/"public"/"data"/{job_id}` (run_job.py:34), video copy target `APP_DIR/"public"/"videos"` (run_job.py:378). storage.py:17–22 mirrors this for the server. You cannot redirect these via env: run_job **overwrites** `JOB_OUTPUT_DIR`/`JOB_PROJECT_DIR` itself (run_job.py:77–78) before importing config. An isolated workspace therefore must reproduce the `modular_pipeline/` + sibling `App/public/` tree (or bind-mount those paths), not just set env vars.
3. **Import-time config freeze**: all `JOB_*` values are read at config import (config.py:12–48); any in-process reuse of pipeline modules across jobs is unsafe. The subprocess-per-job boundary is load-bearing.
4. **Shared-filesystem IPC**: server↔job communication is entirely file-based — `status.json`, `result.json`, `stderr.log`, plus the `App/public/data/{id}` outputs served by Flask (server.py:127–159, 787–794). Splitting server and worker into separate containers requires a shared volume or an explicit artifact sync; nothing else signals completion.
5. **No process handle**: fire-and-forget Popen, no PID file, no timeout, no cancellation (server.py:113–119). In a container you need your own supervision (the adapter should own the child process and its exit code).
6. **Runtime model/weight downloads**: faster-whisper `medium` downloads to `~/.cache/instascribe` on first run (audio_whisperx_pipeline.py:45, 302); silero-vad and Kokoro weights likewise resolve at first use (local_provider.py:8–9). Needs a writable HOME and either egress or a pre-baked cache layer.
7. **Nested subprocess + temp files**: transcription re-execs `sys.executable` with a generated temp script (audio_whisperx_pipeline.py:407–430) and the audio path uses `tempfile.NamedTemporaryFile` (audio_whisperx_pipeline.py:128) — the container needs the same interpreter/venv on PATH-of-exec and a writable system temp dir.
8. **Secrets via inherited env + scattered `.env` loads**: jobs inherit the entire server env (server.py:111); `.env` is loaded from `modular_pipeline/.env` (api_settings.py:7) and repo-root `.env` (tts_render.py:26, factory.py:151, audio_whisperx_pipeline.py:36 cwd-relative). Provide `OPENAI_API_KEY` (or backend equivalents) as real env vars; don't rely on `.env` files being present.
9. **Flat-module imports**: pipeline modules import each other as top-level names (`import config`, run_job.py:93; `import storage`, server.py:25) and depend on `sys.path.insert(0, PIPELINE_DIR)` (run_job.py:91) / cwd = `modular_pipeline` (server.py:115, Dockerfile:27). The workspace must keep `modular_pipeline/` as the working/anchor directory.
10. **Minor**: `MAX_CALLS=100` per-process OpenAI-call ceiling caps long videos at 100 chunks (api_settings.py:9–18); frame extraction spawns one ffmpeg per second of video (frame_extraction.py:52–57) — CPU/PID pressure on long inputs; posters require Pillow (run_job.py:224).

**Safest adapter seam — wrap the run_job.py subprocess, don't touch the pipeline**:
- **What to wrap**: the exact server invocation — `<python> run_job.py <job_id> <settings_json_path>` with `cwd=<workspace>/modular_pipeline` (mirror server.py:113–119). run_job is already a self-contained batch program with argv-only inputs and file-only outputs.
- **What to synthesize** in the temp workspace: (a) the directory skeleton `modular_pipeline/` (code) + `modular_pipeline/jobs/{job_id}/` + sibling `App/public/data/` and `App/public/videos/` (empty dirs suffice — run_job mkdirs the leaves, run_job.py:146–148, 379); (b) `jobs/{job_id}/video.mp4` and `jobs/{job_id}/settings.json` with the server's schema (server.py:77–91) — this file, not env, is the whole job contract; (c) env: `INSTASCRIBE_BACKEND` (+ `VISION_PROVIDER`/`TTS_PROVIDER` overrides if wanted), provider API keys, optionally `HOME`/cache mount for whisper weights; never pre-set `JOB_*` (run_job.py:74–87 clobbers them anyway); (d) optionally seed the `queued` status.json exactly as server.py:96–107 does so pollers never see `not_found`.
- **What to poll**: `jobs/{job_id}/status.json` for `{status,progress,stage,chunks_done,chunks_total,error}` (schema at run_job.py:127–139) **for progress mirroring only** — completion is decided by the child's exit status plus artifact validation, never by `status.json`. Caveats: argv/settings parsing and the pipeline imports run *before* `main()`'s `try/except` (run_job.py:27–114), so a pre-`main()` crash exits nonzero while `status.json` remains absent or stale (`queued`); conversely a nonzero exit does **not** guarantee that `status.json` contains `failed` or a traceback. And `run_job.py` writes legacy `ready` *before* `result.json` (run_job.py:395 vs 398–410), so `ready` must not be trusted as completion. The adapter therefore waits for child exit, treats exit 0 as necessary-but-insufficient, validates the required artifact set — `jobs/{job_id}/result.json` (run_job.py:398–410) and `App/public/data/{job_id}/{scenes,entities,system_info,audio_events,ad_placement_gaps,transcript}.json` + `poster.jpg[/avif]` + `App/public/videos/{job_id}.mp4` (run_job.py:261–384) — and only then reports success. Because the adapter owns the Popen handle, it also gains the kill/timeout control the current server lacks.

Places that break if artifacts move behind presigned S3 URLs via a manifest:

1. Suffix concatenation onto `dataPath` (api.ts:27, 35, 42, 49; demoApi.ts:81, 112): a presigned URL carries a query string, so `${dataPath}/scenes.json` cannot be built by string concatenation; the client would need a manifest mapping artifact-name → URL.
2. `dataPath`/`videoFile`/poster URLs are persisted in localStorage by zustand `persist` (App/src/store/appStore.ts:74–83, `partialize` includes `projects`), so any expiring presigned URL would go stale across sessions/reloads; reconcile only patches when the string differs (uploadApi.ts:139–143).
3. `exportDownloadUrl` is a synchronous URL builder used directly as `href`/`location.href`/`<video src>` (api.ts:214–218; EditorPage.tsx:338, 435, 713) — a presign round-trip would force an async flow.
4. TanStack Query `staleTime` 5 min with keys derived from `projectId` only (App.tsx:8; queryKeys.ts:4–8): cached data survives a URL rotation but any refetch re-uses the stored (possibly expired) `dataPath`.
5. `hasData = !!project?.dataPath` gates the whole editor (EditorPage.tsx:39, 448–471) — a manifest-based flow must still populate something equivalent or rework the gate.
6. Dev proxy prefixes (vite.config.ts:12) assume same-origin `/data` + `/videos`; S3-hosted artifacts bypass it (CORS becomes the frontend's problem).
7. `fetchJson` sends no credentials/headers and expects raw JSON GET (api.ts:12–16) — fine for presigned GETs, but no retry/refresh on 403 (an expired signature surfaces as a thrown `fetch … → 403` with `retry: false` on the editor queries, EditorPage.tsx:60).

### Deployment implications

Current model (what changes from): static SPA build in `App/dist` served **single-origin by Flask** — `/data/*` from `storage.DATA_DIR` (`modular_pipeline/server.py:787-789`), `/videos/*` (`server.py:792-794`), SPA index + catch-all fallback for client routes with `api/` excluded (`server.py:797-812`); demo build keeps `dist/data`+`dist/videos` because "those static fixtures ARE the backend" (`build-demo.sh:6-7,12-14`), study build deletes them so Flask serves per-session copies (`build-study.sh:19-20`); Docker copies `App/dist` + `App/public` beside the Python server (`Dockerfile:20-23`), Fly single process (`fly.toml:16-22`).

A standalone Next.js container behind CloudFront/ALB changes:

- **SPA fallback disappears**: Next's server owns routing, so Flask's catch-all (`server.py:804-812`) and any S3/CloudFront 404→`index.html` rule are no longer needed; deep links (`/editor/:id`, `/dashboard/settings`) become real server responses. The `api/` carve-out logic moves to ALB/CloudFront path routing.
- **Asset paths**: hashed bundles move from `/assets/*` (Vite dist layout) to `/_next/static/*` — CloudFront needs a long-TTL immutable behavior for `/_next/static/*`, no-cache for HTML/RSC payloads. `favicon.svg` link in `App/index.html:5` moves into Next metadata.
- **`/data` + `/videos` serving must be split by mode**: demo fixtures (`App/public/data/…`, `App/public/videos/…`, `App/public/demo/silence.mp3`) ship in the Next `public/` dir; live/study mode instead needs CloudFront/ALB routes (or Next `rewrites`) sending `/data/*`, `/videos/*`, `/api/*` to the Flask/pipeline origin, because per-session data is generated server-side (`server.py:678-679,787-794`). The editor fetches these with **relative** paths (`api.ts:27` `${project.dataPath}/scenes.json`; `dataPath` values like `/data/<id>`, `uploadApi.ts:199`), so origin routing — not code — decides where they resolve. Video `Range` requests must be forwarded/whitelisted for `<video>` seeking (`VideoPanel.tsx:62-68`).
- **Preview/demo mode**: the zero-backend demo (`build-demo.sh`) is the one build that could remain a pure static export (`output: 'export'`) since every write is short-circuited locally (`App/src/lib/demoApi.ts:1-114`); study/normal modes need the Node server (or keep flags baked and produce two images). The `PREVIEW_BACKEND` local-proxy workflow (`vite.config.ts:9-17`) becomes Next dev rewrites.
- **Absolute-URL leak points to re-test**: export download navigations use `API_BASE`-absolute URLs (`api.ts:214-218`, `EditorPage.tsx:435,713`), and restart-demo hard-navigates to `/study` (`EditorPage.tsx:370`) — these bypass client routing and must resolve at the CDN/ALB layer.
